# Языки приложения (RU / KY)

Приложение работает на двух языках: русский (по умолчанию) и кыргызский. Адреса начинаются с `/ru` или `/ky`,
выбор языка запоминается в cookie `NEXT_LOCALE`, переключатель «RU / KY» — в шапке (и на экране входа).

## Куда вписывать кыргызский перевод

Файл **`messages/ky.json`**. Сейчас в нём русский текст-заглушка (копия `messages/ru.json` с тем же набором ключей).
Меняйте только **значения** (текст справа от двоеточия), ключи (слева) не трогайте:

```json
"cart": {
  "title": "Корзина",          ← вписать перевод вместо русского текста
  "empty": "Корзина пуста"
}
```

Структура файла — по разделам: `nav` (меню), `home` (главная), `catalog` (каталог и фильтры), `catalogGroups` и `categories`
(названия категорий и подкатегорий, например «Уход за лицом»), `product`, `cart`, `checkout`, `orders`, `profile`,
`questionnaire`, `skin` / `hair` (типы кожи и волос, советы, порядок ухода), `firstRun` (экраны «Включить уведомления?»
и «Разрешить геолокацию?»), `login`, `resetPassword`, а для админки — `adminHome`, `adminStock`, `orderManager`,
`branchManager`, `adminStaff`, `adminSettings`, `adminCatalog`, `adminImport`, `sources` и др.

Правила:
- Текст в `{фигурных скобках}` (например `{name}`, `{n}`, `{total}`) — подставляемые значения. Оставляйте как есть, можно
  переставлять по смыслу: `"Добавить «{name}» в корзину"`.
- Теги вида `<b>…</b>` внутри текста — выделение; оставляйте.
- Списки (например шаги ухода в `skin.routine.*.morning`) — это массивы `["…", "…"]`: переводите каждый элемент, количество можно менять.
- **Числа во множественном числе.** В русском: `"{count, plural, one {# товар} few {# товара} many {# товаров} other {# товара}}"`.
  В кыргызском форм две — оставьте только `one` и `other`:
  `"{count, plural, one {# товар} other {# товар}}"` (подставьте свои слова). Так сделайте для ключей
  `catalog.productCount` и `questionnaire.years`.
- После правки перезагрузите страницу (в режиме разработки `npm run dev` изменения видны сразу).
- Проверить, что ключи не потерялись: скрипт сверки (см. ниже) или просто откройте страницы `/ky/...`.

## Что намеренно остаётся на русском
- Сообщения, которые уходят в WhatsApp продавцу / покупателю (текст заказа, приветствие филиалу).
- Технические сообщения сервера (ответы `/api/...`, диагностика импорта) — их видит в основном владелец при сбоях.
- Данные из базы: названия и описания товаров, названия брендов, адреса филиалов — переводятся не файлом, а самими данными.
- Сами названия категорий как идентификаторы в базе и ссылках (`?group=Уход за лицом`) — на экране они показываются
  из `messages/*.json`, но в данных остаются русскими.

## Для разработчика
- Новый текст: добавить ключ в `messages/ru.json` **и** `messages/ky.json`, использовать `useTranslations("раздел")` /
  `getTranslations` (сервер). Ссылки и переходы — только через `@/i18n/navigation` (`Link`, `useRouter`, `usePathname`,
  `redirect`), иначе пропадёт префикс языка.
- Суммы — через `usePrice()` (`src/lib/use-price.ts`).
- Маршрутизация языка встроена в `src/proxy.ts` (в Next.js 16 middleware называется proxy) вместе с проверкой входа и ролей.
- В Supabase → Authentication → URL Configuration в **Redirect URLs** должно быть разрешено `https://<сайт>/**` — письма
  подтверждения и сброса пароля теперь ведут на `/ru/login`, `/ky/login`, `/ru/reset-password`, `/ky/reset-password`.
