# Публикация в App Store и Google Play

Приложение — оболочка Capacitor, которая открывает живой сайт (`capacitor.config.ts` → `server.url`). Публикуется под КАЖДОГО
клиента отдельно (своя копия, см. `docs/WHITE-LABEL.md`). Состояние на 07.10.2026: основа готова технически, публикация —
когда будет клиент с настоящим каталогом и брендом.

## 1. Что меняется под клиента (нативная часть)

| Что | Где |
|---|---|
| Идентификатор приложения (после первой публикации менять НЕЛЬЗЯ) | `capacitor.config.ts` → `appId`; Android: `android/app/build.gradle` (`namespace`, `applicationId`) и папка `android/app/src/main/java/<пакет>/` с `MainActivity`; iOS: `PRODUCT_BUNDLE_IDENTIFIER` (2 места) в `ios/App/App.xcodeproj/project.pbxproj` |
| Название под иконкой | Android: `android/app/src/main/res/values/strings.xml` (`app_name`); iOS: `ios/App/App/Info.plist` (`CFBundleDisplayName`); полное — `capacitor.config.ts` → `appName` |
| Адрес сайта | `capacitor.config.ts` → `server.url` (желательно свой домен, а не `vercel.app`) |
| Иконка и заставка | подменить исходник `design/logo-drafts/…`, затем `node scripts/build-brand-assets.mjs` и `node scripts/build-splash-layers.mjs`, затем `npx capacitor-assets generate --ios --android --iconBackgroundColor '#RRGGBB' --iconBackgroundColorDark '#RRGGBB' --splashBackgroundColor '#RRGGBB' --splashBackgroundColorDark '#RRGGBB'` (цвет — фон логотипа клиента) |
| Версии | Android: `versionCode`/`versionName` в `android/app/build.gradle`; iOS: `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` в `project.pbxproj`. Каждая новая загрузка в магазин — версия выше |

После правок конфига/иконок: `npm run cap:sync`.

## 2. Уже сделано в нативных проектах

- Разрешения Android: интернет, геолокация (приблизительная и точная — по желанию человека). CAMERA НЕ объявлено намеренно:
  фото профиля выбирается системным окном, а объявленное CAMERA заставило бы это окно просить отдельное разрешение.
  `uses-feature` для GPS и камеры помечены «не обязательно», чтобы Google Play не скрывал приложение от части телефонов.
- `allowBackup="false"` (личные данные не уходят в облачную копию Android).
- Описания разрешений iOS (`Info.plist`): геолокация, камера, фото; `ITSAppUsesNonExemptEncryption = false` (не спрашивать про шифрование).
- Адаптивная иконка Android (эмблема в безопасной зоне) и иконка iOS без прозрачности, заставки обеих платформ.

## 3. Что нужно от владельца/клиента

- Аккаунт **Apple Developer** (99 $/год) и **Google Play Console** (25 $ разово). Имя разработчика видно покупателям.
- Сборка iOS без Mac — в облаке (Codemagic или аналог): нужны ключ App Store Connect API и сертификаты подписи.
- Google Play: для нового личного аккаунта — закрытое тестирование, не меньше 12 тестировщиков 14 дней подряд, только потом релиз.
- Настоящий каталог и бренд, свой домен и почта (`docs/EMAIL-TEMPLATES.md`), платные тарифы хостинга и базы с бэкапами.

## 4. Перед отправкой на проверку

- [ ] Нет демо-данных (`DEMO-*`, фото с чужими этикетками), нет текстов-заглушек.
- [ ] Тестовый аккаунт для проверяющего: почта подтверждена, пароль в «Notes for review»; у аккаунта есть заказы/корзина.
- [ ] Политика конфиденциальности: адрес `/privacy` на домене клиента (реквизиты в `src/lib/legal.ts`).
- [ ] Удаление аккаунта: в приложении есть (Профиль → «Удалить аккаунт»). Для Google нужна ещё **публичная веб-ссылка**
      с описанием, как удалить аккаунт и данные (страницы пока нет — добавить при подготовке публикации).
- [ ] Анкеты: «Конфиденциальность приложения» (Apple) и «Безопасность данных» (Google) — см. раздел 5.
- [ ] Возрастной рейтинг, категория (Покупки), описание, ключевые слова, скриншоты (iPhone 6.7" и 6.5"; Android — телефон),
      адрес поддержки.
- [ ] Push-уведомления (риск отказа Apple по правилу 4.2 «просто сайт в обёртке»): в оболочке сейчас НЕ работают — нужны
      Firebase (Android) и ключ APNs (iPhone) и плагин `@capacitor/push-notifications`. Сайт и «Домой»-приложение
      получают push уже сейчас (web push).
- [ ] Проверка нативных сборок на реальных телефонах: вход, регистрация по ссылке из письма, геолокация, выбор фото профиля,
      переход в WhatsApp, заказ, удаление аккаунта.

## 5. Какие данные собирает приложение (для анкет)

- Почта, пароль (хранится в зашифрованном виде у Supabase), имя, дата рождения, пол — профиль.
- Тип кожи/волос и проблемы — анкета ухода (по желанию).
- Телефон, адрес доставки, состав заказов — оформление заказа.
- Сообщения обратной связи (с телефоном для связи), отзывы.
- Геолокация — только по согласию; координаты хранятся на устройстве, город определяется внешним сервисом BigDataCloud
  (сторонний сервис получает координаты — указать в политике).
- Фото профиля (по желанию), токен push-уведомлений (по согласию).
- Платёжных данных приложение НЕ собирает: оплата вне приложения (продавец в WhatsApp). Реклама и сторонняя аналитика не подключены.
- Данные не продаются; удаление аккаунта удаляет профиль и корзину, заказы остаются у магазина без привязки к аккаунту.

## 6. Что НЕ проверено на момент записи

Нативные сборки (нет Xcode и Android SDK на этом компьютере): манифест и `Info.plist` проверены как корректные файлы, но
сам запуск в Android Studio / Xcode и на телефоне не выполнялся.
