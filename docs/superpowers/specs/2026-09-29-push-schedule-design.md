# Рассылка: изменить / удалить, запланировать, срок действия — 29.09.2026

Просьба владельца: в «Реклама и акции» → «Рассылка» — менять и удалять сохранённые уведомления, планировать отправку, сроки.
Решения владельца: «сроки» = срок действия «до» (например, акция до 05.10); менять можно только запланированные (ещё не
отправленные); отправленные — только удалить из истории.

## Поведение
- Форма: заголовок, текст, что открыть, **Когда отправить** — «Сейчас» / «Запланировать» (дата ДД.ММ.ГГГГ и время ЧЧ:ММ вводом
  цифр, как в «Продажах»; время телефона), **Действует до** (необязательно, дата).
- Срок «до»: к тексту уведомления добавляется «До 05.10»; телефоны, которые были выключены, после этой даты старую рассылку
  уже не получат (TTL до конца дня «до», не больше 28 дней); запланированная на дату позже срока — не отправится. В истории — «Закончилась».
- История: «Запланировано на 05.10 10:00» — кнопки «Изменить» (форма переходит в режим правки) и «Отменить» (удаляет);
  «Отправляется…»; «Доставлено на N · дата» — кнопка «Удалить из истории»; «Закончилась» (срок прошёл).

## База (`supabase/push_schedule.sql`)
- `push_broadcasts` + `scheduled_at timestamptz`, `valid_until date`, `status` (scheduled | sending | sent), `sent_at`.
- BEFORE INSERT: `status` = scheduled, если `scheduled_at` в будущем, иначе sending; AFTER INSERT: sending → `notify_push`.
- BEFORE UPDATE: не-запланированную нельзя менять (заголовок, текст, ссылка, время, срок) — только служебные поля статуса.
- pg_cron раз в минуту: `send_due_broadcasts()` — запланированные с наступившим временем → sending → `notify_push`.
- Edge Function `send-push`: пропускает, если срок прошёл; ставит sent + sent_at + sent_count; TTL по сроку; текст «До …» —
  `broadcastMessage` в `messages.ts` (тест).
