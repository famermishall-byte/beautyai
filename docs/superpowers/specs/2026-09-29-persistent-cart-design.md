# Корзина за аккаунтом + частичное оформление заказа — дизайн

Дата: 2026-09-29. Статус: дизайн согласован с владельцем в чате («да»).

## Проблема (со слов владельца)

«В корзине сразу все товары оформляются, есть выбор удалить товар или добавить, но после оформления заказа
корзина пуста, а я хочу чтобы товары, которые клиент решил убрать с заказа, оставались потом в корзине.»

Как сейчас (проверено по коду):
- `src/lib/cart-context.tsx` хранит корзину в `localStorage["beautyai-cart"]` — только на этом устройстве,
  не привязана к аккаунту.
- `CartDrawer.tsx` → кнопка «Оформить» → отдельная страница `/checkout` (3 шага: филиал → контакты → проверка).
- `POST /api/orders` принимает ВЕСЬ массив `items` от клиента (включая цены!) и создаёт заказ; страница
  после успеха вызывает `clearCart()` — корзина пустеет целиком.
- Единственный способ «не заказывать» товар — удалить его, и он пропадает насовсем.

## Решения владельца

1. Выбор товаров для заказа — **галочки** у каждого товара (по умолчанию отмечены).
2. Корзина хранится **за аккаунтом** (видна на любом устройстве после входа).
3. Заказ оформляется **прямо в выезжающей корзине**, без отдельной страницы.
4. Товар уходит из корзины только когда: (а) клиент сам нажал «удалить», или (б) товар был отмечен и
   заказ по нему успешно оформлен. Больше ничего корзину не очищает (ни выход из аккаунта, ни время).

## Данные

Новая таблица `public.cart_items` (миграция `supabase/cart_items.sql`, применяется к живой базе только с
отдельного «да» владельца):

| колонка      | тип                                  | примечание                                   |
|--------------|--------------------------------------|----------------------------------------------|
| `user_id`    | uuid → `auth.users(id)` on delete cascade | удаление аккаунта удаляет корзину         |
| `product_id` | uuid → `products(id)` on delete cascade   | товар удалён из каталога → пропал из корзин |
| `quantity`   | int, check `quantity > 0`            |                                              |
| `selected`   | boolean not null default true        | галочка «в заказ»                            |
| `created_at` | timestamptz default now()            | порядок показа — как добавляли               |
| `updated_at` | timestamptz default now()            |                                              |

PK `(user_id, product_id)`. RLS включён; четыре политики `cart_items_*_own` (select/insert/update/delete)
с `user_id = auth.uid()`. Сотрудникам доступа к чужим корзинам не даём — им не нужно.

Отвергнутый вариант: jsonb-поле корзины в `profiles` — у `profiles` колоночные гранты на update (уже
спотыкались), и в нём копились бы устаревшие цены/названия товаров.

## API (`src/app/api/cart/route.ts`)

Все ручки требуют сессию (`getSessionProfile()`), работают через серверный Supabase-клиент под RLS.

- `GET /api/cart` → `{ items: CartItem[] }` — строки `cart_items` пользователя, join с `products`
  (только товары своего `store_id`), маппинг через `mapProduct`, сортировка по `created_at`.
- `POST /api/cart` `{ productId, delta }` — добавить/изменить количество (upsert; итог ≤ 0 → удалить строку).
  Новый товар приходит с `selected = true`.
- `PATCH /api/cart` `{ productIds: string[] | "all", selected: boolean }` — галочки (одна или «выбрать все»).
- `DELETE /api/cart?productId=…` — удалить товар из корзины.
- `POST /api/cart/merge` `{ items: { productId, quantity }[] }` — одноразовый перенос старой
  localStorage-корзины в аккаунт (складывает количества с уже имеющимися).

## Оформление заказа (`POST /api/orders`, переделка)

Тело: `{ branchId, customerName, customerPhone }` — **без items**. Сервер:
1. берёт из `cart_items` строки пользователя с `selected = true` (пусто → 400 «Отметьте хотя бы один товар»);
2. берёт цену, название, бренд, SKU **из `products`**, а не от клиента (закрывает текущую возможность
   подменить цену в запросе);
3. проверка остатков в филиале — без изменений (как сейчас, 409 с перечнем);
4. создаёт заказ и WhatsApp-ссылку — как сейчас;
5. удаляет из `cart_items` ровно заказанные строки. Если это удаление не удалось — заказ всё равно
   считается оформленным (он уже в базе), клиент просто увидит эти товары в корзине и удалит сам;
   ответ не падает.

`GET /api/orders` не меняется.

## Клиент

### `cart-context.tsx`
- Источник правды — сервер. При появлении сессии покупателя: `GET /api/cart`; при смене/выходе — корзина
  в памяти сбрасывается (не на сервере). localStorage-кэш корзины больше НЕ ведётся (иначе на общем
  устройстве корзина одного аккаунта мелькала бы у другого).
- Миграция: если в `localStorage["beautyai-cart"]` что-то есть — один раз `POST /api/cart/merge`, после
  успеха ключ удаляется.
- Изменения оптимистичные (сразу видно), затем запрос; при ошибке — перезагрузка корзины с сервера и
  короткое сообщение об ошибке.
- Интерфейс для остальных компонентов сохраняется (`items`, `addItem`, `removeItem`, `changeQuantity`,
  `totalCount`, `hydrated`), добавляются: `toggleSelected(id)`, `setAllSelected(bool)`,
  `selectedCount`, `selectedTotal`, `reload()`. `clearCart` удаляется. `CartItem` получает `selected: boolean`.
  `ProductCard`, `CareKitView`, `BuyAgainModal`, страница товара — без изменений логики.
- Сотрудники в админке — корзина не грузится (как и сейчас кнопка скрыта при `isAdmin`).

### `CartDrawer.tsx` (разбить на части, файл уже большой)
- `CartDrawer` — кнопка + оболочка шторки, переключает три вида: список → форма → «Заказ отправлен».
- `CartItemRow` — строка: галочка, название/бренд, −/+ , удалить, сумма.
- `CartCheckoutForm` — филиал (предвыбор из `localStorage["beautyai-branch"]`, как в каталоге), имя и
  телефон (предзаполнение из последнего заказа через `GET /api/orders`, иначе имя из профиля),
  кнопка «Отправить в WhatsApp» (активна, если отмечен ≥ 1 товар, выбран филиал, заполнены имя/телефон).
- Вид «Заказ отправлен» — перенос текущего экрана успеха со страницы `/checkout` (номер заказа,
  предупреждение «нажмите Отправить в WhatsApp», кнопка «Открыть WhatsApp снова»), затем «Готово» —
  закрывает шторку; в корзине остаются неотмеченные товары.
- Над списком: «Выбрать все» / счётчик; итог «Итого (N товаров)» — только по отмеченным.
- Баннер, который раньше показывался на `/checkout` (`BannerGate page="checkout"`), показывается при
  открытии шторки — то же правило «раз за посещение».

### `/checkout`
Страница заменяется редиректом на главную (старые ссылки/закладки не ломаются). Условие
`pathname.startsWith("/checkout")` в `CartDrawer` удаляется.

### Прочее
- `login/page.tsx` `clearStaleCart()` и удаление ключа в `profile/page.tsx` — оставить (теперь это просто
  уборка устаревшего ключа), корзину за аккаунтом они не трогают.
- Все новые строки интерфейса — в `messages/ru.json` и `messages/ky.json`.
- Стиль — как у текущих экранов (DESIGN.md, существующие `Button`, токены), без нового редизайна.

## Ошибки и крайние случаи

- Товар закончился в выбранном филиале → текущее сообщение 409 остаётся, корзина не трогается.
- Товар удалён из каталога → каскадно пропал из корзин.
- Нет сети при изменении → сообщение, корзина перезагружается с сервера при следующей удаче.
- Два устройства одновременно → последнее изменение побеждает; при открытии шторки корзина
  перезапрашивается с сервера.

## Проверка

- `npx tsc --noEmit`, `eslint`, `npm run build` — чисто.
- В браузере (Playwright, 390×844) на тестовом аккаунте (после — удалить аккаунт и его данные):
  1. добавить 3 товара, снять галочку с одного, оформить → в заказе 2, в корзине остался 1;
  2. выйти и войти снова → товар на месте;
  3. положить в `localStorage["beautyai-cart"]` старую корзину → после входа она в аккаунте, ключ удалён;
  4. «Выбрать все», удаление, изменение количества, отправка без галочек заблокирована;
  5. проверить, что в `orders.items_json` цены из каталога.

## Вне рамок

- Push-уведомления, оплата, доставка — не трогаем.
- Сохранение корзины для незалогиненных — в приложении нет гостевого режима (proxy требует вход).
