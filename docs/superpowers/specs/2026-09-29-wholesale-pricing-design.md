# Оптовые цены — дизайн

Дата: 2026-09-29. Статус: дизайн согласован с владельцем в чате («начинай»).

## Задача (со слов владельца)

Клиент-магазин пишет: «от 1000 долларов можно оптом набирать, то есть все товары понемногу, и от 1000 долларов
будет уже оптовая цена». Как именно магазин считает оптовую цену — пока неизвестно, поэтому владелец просит
сделать несколько вариантов, которые админ выбирает сам.

## Решения владельца

1. Порог — сумма ЗАКАЗА (любые товары понемногу); от порога на все отмеченные товары действует оптовая цена.
2. Способ расчёта выбирает админ: «Выключено» / «Скидка % на все товары» / «Своя оптовая цена у товара».
3. Порог задаётся в долларах + курс доллара (админ вводит вручную); приложение пересчитывает в сомы.
4. Покупатель видит: полоску прогресса в корзине и плашку на главной. Оптовую цену в каталоге — НЕ показываем.

## Правила расчёта (единая чистая функция `src/lib/wholesale.ts`, с тестами)

- `порог_сом = round(threshold_usd × usd_rate)`.
- Порог проверяется по сумме отмеченных товаров по ОБЫЧНОЙ цене (с учётом акции) — оптовая скидка не может
  «выбить» заказ обратно ниже порога.
- Оптовая цена единицы товара:
  - «Скидка %»: `round(базовая_цена × (100 − p) / 100)` (базовая = каталожная `products.price`, до акции);
  - «Своя цена»: `products.wholesale_price`; если не заполнена — у товара нет оптовой цены, он идёт по обычной;
  - «Выключено» или не задан курс — опта нет.
- Итоговая цена товара в оптовом заказе = МЕНЬШАЯ из (обычная цена с акцией, оптовая цена).
- Ниже порога — все товары по обычной цене. На сумму влияют только отмеченные товары.
- Всё считает СЕРВЕР (`loadCart` → те же функции): цена от клиента не принимается, как и сейчас.

## Данные (миграция `supabase/wholesale.sql`, к живой базе — только с «да» владельца)

- `stores`: `wholesale_mode text not null default 'off'` (check: off | percent | per_product),
  `wholesale_percent numeric` (0 < p < 100, nullable), `wholesale_threshold_usd numeric not null default 1000`
  (> 0), `usd_rate numeric` (> 0, nullable).
- `products`: `wholesale_price numeric` (> 0, nullable).
- `orders`: `is_wholesale boolean not null default false`.
Права: у `stores`/`products` гранты на уровне таблицы — новые колонки доступны без отдельных grant; обновлять
`stores` может только owner/admin (существующая политика `stores_update_own_admin`).

## Админка

- «Магазин» (`/admin/profile`): новый блок «Оптовые цены» — способ (3 варианта), процент (для «Скидки %»),
  порог в $, курс доллара, живой пересчёт «= N сом». Сохраняется через `PUT /api/admin/store` (расширить) или
  отдельный `PUT /api/admin/wholesale`. Для «Своей цены» — строка «у N товаров оптовая цена не заполнена».
- «Каталог» (`/admin/catalog`): колонка «Опт» (оптовая цена товара или «—»).
- Загрузка Excel (`/admin/products`, `fields.ts`) и синхронизация (`syncFields.ts`, `sync.ts`,
  `executeSync.ts`): необязательная колонка «Оптовая цена» (псевдонимы: «оптовая цена», «опт», «цена опт»,
  «оптом», «wholesale», «wholesale price»). Пустая/некорректная — не ошибка строки, просто без оптовой цены
  (некорректная — предупреждение в предпросмотре не требуется; значение игнорируется).
- Защита автосопоставления (`autoMap.ts`): поле «Цена» не должно захватывать колонку, в заголовке которой есть
  «опт»/«wholesale» (иначе при заголовке «Цена, сом» правее «Оптовой цены» обычная цена бралась бы из оптовой).
- Список заказов: у оптового заказа метка «Опт».

## Покупатель

- Корзина (`CartDrawer`/`CartCheckoutForm`): при включённом опте — блок над итогом:
  ниже порога «До оптовых цен осталось N сом» + полоска прогресса; от порога «Оптовые цены применены — вы
  экономите N сом». В строках товаров при оптовом заказе — оптовая цена, обычная зачёркнута. Итог — оптовый.
- Главная: плашка «Опт от 1 000 $ (≈ 87 500 сом) — цены ниже», только когда опт включён и курс задан.
  Данные — `GET /api/wholesale` (включён ли, порог $ и сом).
- Все новые строки — `messages/ru.json` и `messages/ky.json`.

## Заказ

`POST /api/orders`: `loadCart(selectedOnly)` → применить опт → строки заказа с итоговыми ценами,
`total_price` — оптовый итог, `is_wholesale = true`, в сообщении WhatsApp строка «Оптовый заказ (от N сом)».
Проверка остатков — без изменений.

## Проверка

- Автотесты: `wholesale.ts` (три способа, порог по обычной цене, акция vs опт, неотмеченные не считаются,
  нет курса → нет опта, округление), `autoMap` (оптовая колонка не уходит в «Цену»; распознаётся как опт).
- tsc / eslint / build.
- Браузер (390×844), временный аккаунт (после — удалить): ниже порога полоска; выше — оптовые цены и экономия;
  заказ — оптовые цены в `items_json`, `is_wholesale`, строка в WhatsApp. Настройки менять на живой базе только
  на время теста и вернуть «Выключено» (если владелец не скажет иначе).

## Вне рамок

- Разные пороги/цены по филиалам, уровни опта (от 1 000 $, от 5 000 $), отдельные «оптовые клиенты».
- Оптовая цена в каталоге и на странице товара (владелец не выбрал).
- Автоматический курс из интернета.
