# Смена бренда: что менять, когда приложение покупает другой магазин

Решение (03.10.2026): новому клиенту делается **отдельная копия** приложения (свои база, сайт, домен, почта).
Одной общей системы на много брендов не строим. Ниже — всё, что в коде и в сервисах привязано к «ОПТОВЫЕ ЦЕНЫ 01».
Порядок восстановления с нуля — `docs/RECOVERY.md`; здесь только то, что именно меняется под нового клиента.

## 1. Что нужно получить от клиента

- Название магазина, логотип (лучше квадратный, от 1024 пикселей; сейчас файл 223×233 — иконки мягкие), основной цвет.
- Каталог товаров (Excel) и фото; список филиалов с адресами, точными координатами, WhatsApp-номерами.
- Реквизиты для политики конфиденциальности: название или ИП, контакт для обращений.
- Страна, валюта, языки интерфейса (сейчас русский и кыргызский), часовой пояс.
- Домен сайта и доступ к его настройкам (если есть).

## 2. Что менять в коде (место → что)

| Что | Где |
|---|---|
| Название в шапке, на заставке, в письмах | берётся из базы (`stores.name`) — менять там, кодом не надо |
| Название на иконке приложения, во вкладке браузера, в уведомлениях | `src/app/manifest.ts`, `messages/ru.json` и `messages/ky.json` (раздел `meta`), `public/sw.js` |
| Слоган на заставке | `messages/*.json`, ключ `tagline` |
| Цвет бренда `#c8135f` и тёмный `#970e49` | `src/app/globals.css` (`--accent`, `--accent-strong`), `src/app/manifest.ts`, `src/app/[locale]/layout.tsx` (`themeColor`), `src/app/global-error.tsx`, `src/components/BranchMap.tsx`, `src/components/ui/Button.tsx` (тень), `scripts/build-brand-assets.mjs` |
| Логотип и все иконки | положить новый файл в `design/logo-drafts/`, запустить `scripts/build-brand-assets.mjs` (делает иконки сайта, значок в приложении и иконки/заставки Android и iOS). После запуска `capacitor-assets` удалить лишнее — см. заметку в `PROJECT_CONTEXT.md` |
| Картинки категорий (товары для красоты) | `public/brand/categories/`, `scripts/build-category-art.mjs` — если у клиента другая тематика, заменить |
| Приложение в Android/iOS | `capacitor.config.ts` (`appId`, `appName`, адрес сайта), папки `android/`, `ios/` |
| Имя пакета | `package.json` (`name`) — необязательно |
| Реквизиты в политике | `src/lib/legal.ts` |
| Адрес сайта в функции уведомлений | `supabase/functions/send-push/index.ts` (`SITE`) |
| Страна, валюта, часовой пояс | код страны 996 для WhatsApp — `src/lib/whatsapp.ts`; слово «сом» — ключ `common.price` в `messages/*.json`; курс доллара и порог опта — в админке «Магазин»; UTC+6 — `supabase/functions/send-push/messages.ts` и `src/lib/backup.ts` |
| Языки | `src/i18n/routing.ts` (сейчас `ky` по умолчанию, `ru`); для нового языка — новый файл в `messages/` |

**Не менять:** префикс `beautyai-` в названиях сохранений на телефоне (`beautyai-cart`, `beautyai-city` и т. п.) — это внутренние
имена, покупателю не видны; переименование сбросит у уже зашедших людей город, филиал и подсказки.

## 3. Что настраивается вне кода (новые аккаунты клиента)

1. **Supabase** — новый проект, затем `docs/RECOVERY.md`: схема из `supabase/00_base_schema.sql` и остальные файлы по порядку из «СНИМКА»
   в `PROJECT_CONTEXT.md`. Адрес проекта вписать в `src/lib/supabase/config.ts` или в переменные окружения; в `supabase/push.sql` — адрес
   функции. Хранилища (бакеты) `avatars` и `banners` создаются SQL-файлами.
2. **Vercel** — новый проект из того же репозитория (или копии), переменные окружения: `SUPABASE_URL`, `SUPABASE_ANON_KEY`,
   `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`; регион `fra1` в `vercel.json`.
3. **Почта** — свой аккаунт Brevo, адрес отправителя клиента, SMTP в Supabase; в «Confirm signup» вставить письмо со ссылкой
   `{{ .SiteURL }}/api/auth/confirm?token_hash={{ .TokenHash }}&type=email`; Site URL и Redirect URLs — адрес нового сайта.
4. **Уведомления в браузере** — новые ключи VAPID (публичный в `src/lib/push.ts`, закрытый в секретах функции `send-push` и в Vault).
5. **Домен** — подключить в Vercel; обновить Site URL, `capacitor.config.ts`, `send-push`. Со своим доменом письма реже попадают в спам.
6. **Данные в базе** — название магазина, филиалы, слайды и баннеры главной, настройки опта; роль владельца выдать клиенту (`profiles.role`).
7. **Демо-данные не переносить:** товары `DEMO-*`, `public/demo/`, поддельные оптовые цены и остатки 500 — только у нас.

## 4. Магазины приложений (если нужно)

Аккаунты разработчика клиента (Google Play, Apple — платный), сборка Android/iOS, настоящие уведомления на телефон (Firebase и Apple),
тексты разрешений (геопозиция, уведомления), ссылка на политику конфиденциальности.

## 5. Проверка перед сдачей

- Войти владельцем, администратором, управляющим филиала и покупателем — у каждого свой набор экранов.
- Оформить заказ (самовывоз и доставка), пройти шаги продавца по ссылке из WhatsApp.
- Зарегистрироваться на новую почту: письмо пришло, ссылка входит в аккаунт.
- Скачать копию данных (Магазин → «Скачать копию»); проверить главную на телефоне и в браузере.

Время (моя оценка, не обещание): чистая копия при готовых материалах клиента — около рабочего дня; основное время уходит на
каталог, фото и аккаунты, а не на код.
