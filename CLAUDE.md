# Beauty (бывший BeautyAI)

Витрина и заказы для магазина косметики «ОПТОВЫЕ ЦЕНЫ 01» (Бишкек): каталог, корзина, заказ уходит продавцу
в WhatsApp. Оплаты и доставки внутри приложения нет. Продукт — `PRODUCT.md`, дизайн — `DESIGN.md`.

**Перед работой прочитать «СНИМОК ПРОЕКТА» — первые ~55 строк `PROJECT_CONTEXT.md`.** Там статус, договорённости
с владельцем и что дальше. Остальной файл (журнал по датам, >200 КБ) целиком не читать — искать нужный раздел по
заголовку.

## Команды

- `npm run dev` — локально на http://localhost:3000
- `npm run build` — сборка (то же делает Vercel)
- `npm run lint` — ESLint
- `npm test` — тесты (`tsx --test`). Список файлов в `package.json` ведётся вручную: новый `*.test.ts` нужно
  дописать в скрипт `test`, иначе он не запускается.
- `npx tsc --noEmit` — проверка типов
- `npm run cap:sync` — только если менялись конфиг, плагины или иконки Capacitor

## Стек и структура

Next.js 16 (App Router) + React 19 + TypeScript + Tailwind 4, Supabase (Postgres, RLS, auth), next-intl (RU/KY),
Capacitor-оболочка для Android/iOS (загружает тот же живой сайт), деплой на Vercel из `main`.

- `src/app/[locale]/(app)` — экраны покупателя и `/admin`; `(auth)` — вход; `o`, `c` — публичные страницы по
  ссылке с токеном (заказ для продавца, курьер)
- `src/app/api` — серверные маршруты; сессию проверяют сами через `getSessionProfile()`
- `src/proxy.ts` — проверка доступа и локаль перед каждой страницей (в Next 16 это замена `middleware.ts`)
- `src/lib` — бизнес-логика и её тесты; `src/lib/supabase` — клиенты; `src/lib/permissions.ts`, `auth.ts` — роли
- `src/components`, `src/components/ui` — компоненты; кнопки только через `ui/Button.tsx`
- `messages/ru.json`, `messages/ky.json` — тексты интерфейса
- `supabase/*.sql` — схема базы; `supabase/functions/send-push` — функция на Deno (вне `tsconfig`)
- `scripts/` — генераторы каталога и демо-данных; `docs/RECOVERY.md` — восстановление с нуля

## Правила

- **Дизайн**: только токены из `src/app/globals.css` и правила `DESIGN.md`. Шрифт Manrope, акцент `#c8135f`.
- **Тексты**: любую строку интерфейса добавлять сразу в оба файла — `ru.json` и `ky.json`.
- **База**: изменение схемы — новым файлом в `supabase/`, применять через коннектор Supabase (проект
  `nufmsvwkixnfjvzdabmz`) и записать порядок запуска в «СНИМОК ПРОЕКТА». У `profiles` право UPDATE выдано
  по колонкам: новую колонку, которую пользователь меняет сам, нужно добавить в GRANT отдельно.
- **Роли**: владелец, администратор, управляющий филиала, покупатель. Каждое изменение доступа проверять
  и в RLS, и в `src/proxy.ts`, и в API-маршруте.
- **Демо-данные** (`DEMO-*`, `public/demo/`) не удалять и не заменять без запроса владельца.
- **Не менять то, что уже одобрено** владельцем; закрытые темы (см. снимок) не поднимать.
- `.env` и `package-lock.json` Claude не редактирует (стоит хук). `ANTHROPIC_API_KEY` не подключаем.
- После правки `.ts`/`.tsx` хук сам запускает `tsc --noEmit` и ESLint по изменённому файлу.
- После законченной правки — коммит и запись в конец `PROJECT_CONTEXT.md` (дата, что сделано, что осталось).
